L'index 5D

Cinq vues simultanées de votre codebase : carte de projet, lexicale, vectorielle, symboles, historique Git. L'agent comprend votre code en profondeur, même sans documentation. Les agents classiques n'ont qu'une seule vue.

Ce que chaque dimension voit. Ce qu'elle empêche.

Carte de projet

Voit l'architecture globale : modules, dépendances, effets de bord. Empêche les structures hallucinées et les modifications qui ignorent comment le système s'assemble réellement.

Recherche lexicale + vectorielle

Retrouve tout, par texte exact ou par sens, sans savoir où chercher. Empêche les occurrences manquées et la logique dupliquée éparpillée dans la codebase.

Symboles / AST

Voit les call sites exacts de chaque fonction, type et variable. Empêche les refactors partiels qui compilent mais laissent des chemins obsolètes derrière eux.

Historique Git

Voit comment le code a évolué et pourquoi. Trace une régression jusqu'au commit exact qui l'a introduite, au lieu de deviner.

À l'intérieur de l'index.

Tout l'index, y compris les embeddings vectoriels, est calculé et stocké sur votre disque local. Il ne quitte jamais votre machine : voir Souveraineté des données.

Ce que ça rend possible.

Cette profondeur de compréhension est ce qui rend les grands projets legacy praticables, et ce qui permet aux tâches difficiles de réussir au lieu de s'enliser. Le refactor documenté dans cette publication en est un exemple : ↗ Étude de cas complète, publiée sur arXiv.

Cela rend aussi votre livraison immunisée contre le turnover : la connaissance architecturale qui ne vivait que dans la tête des développeurs historiques est capturée, figée et instantanément disponible pour n'importe qui sur le projet.
